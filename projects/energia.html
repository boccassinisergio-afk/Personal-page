Analisi Consumi e Prezzi Energia ElettricaEnergy Consumption & Pricing Analysis

2026· stabilestable

Un piccolo sistema che simula il lavoro di un data analyst su un caso reale: calcolare la bolletta di ogni utente incrociando i consumi con tariffe orarie diverse, individuare il picco di consumo e la fascia più costosa, e restituire un report leggibile. A small system that simulates a data analyst's typical task: calculating each user's bill by combining energy consumption with time-based pricing, finding peak usage and the most expensive pricing tier, and producing a readable report.

python sql bigquery pandas matplotlib

Il problemaThe problem

Calcolare una bolletta elettrica richiede di incrociare i consumi orari di ogni utente con fasce tariffarie diverse (F1, F2, F3), individuarne il picco di consumo e la fascia che pesa di più sul totale. Il progetto costruisce questa pipeline da zero, dallo schema del database al report finale. Calculating an electricity bill means matching each user's hourly consumption against different pricing tiers (F1, F2, F3), and finding their peak usage and the tier that weighs most on the total. The project builds this pipeline from scratch, from the database schema to the final report.

PipelinePipeline

  • SQL (BigQuery) crea schema e tabelle, popola dati di esempioSQL (BigQuery) creates the schema and tables, seeds sample data
  • SQL calcola importi, picco di consumo e fascia più costosa per ogni utenteSQL computes billing amounts, peak consumption and the most expensive tier per user
  • Python esegue le query da BigQuery, elabora i risultati con pandas e produce un report testuale più un grafico riassuntivoPython runs the queries against BigQuery, processes the results with pandas, and produces a text report plus a summary chart

Dettagli tecniciTechnical details

  • Join su intervalli orari semi-aperti: le fasce tariffarie sono definite come [ora_inizio, ora_fine), con un ramo di logica dedicato per la fascia che attraversa la mezzanotte (23:00-06:00), per evitare doppi conteggi o buchi ai confini Join on half-open time intervals: pricing tiers are defined as [start_hour, end_hour), with dedicated logic for the tier crossing midnight (23:00-06:00), avoiding double counting or gaps at the boundaries
  • Window function MAX(kwh_consumati) OVER (PARTITION BY id_utente) per il picco di consumo, e QUALIFY ROW_NUMBER() OVER (...) = 1 per isolare la fascia più costosa per utente, con tie-break esplicito Window function MAX(kwh_consumati) OVER (PARTITION BY id_utente) for peak consumption, and QUALIFY ROW_NUMBER() OVER (...) = 1 to isolate each user's most expensive tier, with an explicit tie-break
  • pandas oltre le basi: merge multipli con gestione di colonne omonime, pivot con indice composto, e la combinazione cumsum + shift per calcolare le basi delle barre impilate nel grafico, senza hardcodare somme parziali pandas beyond the basics: multiple merges with duplicate-column handling, a pivot on a composite index, and the cumsum + shift combination to compute stacked-bar base values without hardcoding partial sums

Nota sul datasetA note on the dataset

Il dataset è sintetico (un solo giorno campione, 3 utenti): una scelta deliberata, perché l'obiettivo del progetto è dimostrare l'integrazione tra SQL avanzato, Python e pandas, non gestire scala reale. The dataset is synthetic (a single sample day, 3 users): a deliberate choice, since the project's goal is demonstrating the integration of advanced SQL, Python and pandas, not handling real-world scale.
