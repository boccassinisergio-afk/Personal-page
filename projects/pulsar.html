Pulsar

2025· stabilestable

Un tool CLI che estrae dati strutturati da descrizioni in testo libero dei tuoi progetti e contenuti pubblicati, senza input manuale campo per campo. Incolli una frase, ottieni un record strutturato. A CLI tool that extracts structured data from free-text descriptions of your projects and published content, no manual field-by-field input. Paste a sentence, get a structured record.

python regex json csv oop

Il problemaThe problem

Tenere traccia di ogni progetto costruito e contenuto pubblicato richiede normalmente di compilare campi uno per uno: nome, tecnologie, stato, link. Pulsar elimina quel passaggio: incolli la frase con cui descriveresti naturalmente il progetto, e il tool estrae da solo i campi strutturati. Keeping track of every project built and piece of content published usually means filling in fields one by one: name, technologies, status, link. Pulsar removes that step: paste the sentence you'd naturally use to describe the project, and the tool extracts the structured fields on its own.

Come funzionaHow it works

All'avvio, Pulsar carica le categorie di skill da file JSON nella cartella data/ e compila i pattern a runtime. Quando incolli del testo libero, la regex estrae i campi e le categorie di skill riconosciute; ogni record diventa un oggetto tipizzato (Software o Contenuto), salvato in data.json ed esportabile in CSV in qualsiasi momento. At startup, Pulsar loads skill categories from JSON files in the data/ folder and compiles the patterns at runtime. When you paste free text, regex extracts the fields and recognized skill categories; each record becomes a typed object (Software or Contenuto), saved to data.json and exportable to CSV anytime.

Esempio di input: "ho creato un tool chiamato Pulsar usando python e json, è completato, link https://github.com/..." diventa automaticamente un record con nome, tecnologie, stato e link già separati nei rispettivi campi. Example input: "ho creato un tool chiamato Pulsar usando python e json, è completato, link https://github.com/..." automatically becomes a record with name, technologies, status, and link already split into their own fields.

ArchitetturaArchitecture

Ogni voce è un oggetto tipizzato, non un dizionario slegato. Una classe base Entry contiene i campi comuni (data, link); le sottoclassi Software e Contenuto aggiungono i propri campi e riusano il genitore tramite super(). to_dict() converte un oggetto in dizionario per JSON/CSV, from_dict() (un classmethod) lo ricostruisce. Il salvataggio e il report chiamano to_dict() senza conoscere il tipo concreto: è polimorfismo, la stessa riga di codice funziona per entrambi i tipi di voce. Each entry is a typed object, not a loose dictionary. A base Entry class holds the common fields (data, link); the Software and Contenuto subclasses add their own fields and reuse the parent through super(). to_dict() converts an object to a dictionary for JSON/CSV, from_dict() (a classmethod) rebuilds it. Saving and reporting call to_dict() without knowing the concrete type: that's polymorphism, the same line of code works for both entry types.
